# Spark Studio · 产品说明

本文描述个人知识工作台（仓库名 spark-studio）的背景、愿景，以及当前已落地的功能模块。讨论过程与拍板记录见 [design-history.md](./design-history.md)。界面绘图约束见 [product-design-spec.md](./product-design-spec.md)。给下一任 AI 的阅读顺序见 [README.md](./README.md)。

---

## 1. 背景

知识工作通常被拆在几套互不相通的系统里：

- **读**：知乎收藏、网页、PDF，进来的是别人的文章。
- **记**：笔记软件里的长文和树状目录。
- **做**：待办列表，和刚才读过、写过的东西对不上。
- **学**：想把一批材料变成一门课，大纲、讲义和练习各写各的。
- **写**：公众号、小红书、知乎专栏各自一套后台，同一篇稿要复制三遍。

常见做法是再做一个「什么都登录」的客户端：爬知乎、登微信、对接小红书。这样产品会变成平台附属，账号风险大，也很难把「正在看的这一篇」交给 Agent 处理。

Spark Studio 走另一条路：工作台是**知识中枢**，不是平台客户端。

- 外部 Agent 负责从知乎等地方把标题和 Markdown 推进来。
- 人在站内阅读、整理、设计课程、改稿；右侧 Agent 永远对着当前这条知识说话。
- 外部 Agent 再把已准备好的平台变体取走去发布。工作台不登录知乎、公众号、小红书。

输入、加工、输出是一条链，底层共用一套知识条目。

---

## 2. 愿景

做成给一个人用的知识工作台：能把外面的收藏变成自己的笔记、待办、课程和可发布文稿，并且每一步都有贴在当前条目上的 Agent。

具体目标：

1. **进得来**：收藏夹是输入端。不抓站、不扫码，外部 Agent 经 HTTP MCP 写入标题 + Markdown。
2. **站得住**：Wiki、待办、课程、出稿都吃同一类知识对象（标题 + 正文 + 链接），模块只是不同界面。
3. **问得着**：一条知识一份对话。切到哪一篇、哪一页、哪一课时，右栏就跟哪一条；离开再回来可以续。
4. **出得去**：出稿只准备素材包（标题、正文、摘要、标签、配图说明），标成可导出后交给外部 Agent 发布。
5. **自己能开**：单用户。可以本机跑，也可以放到公网，用登录挡住外人。Cursor API Key 和 MCP token 只存在本机 `.env`。

不做团队协作、不做第二个微信后台、不做通用聊天机器人。Agent 必须看见你正在看的东西，而不是一个全局对话框横跨所有模块。

## 3. 产品原则

| 原则 | 含义 |
| --- | --- |
| 一套条目，多种视图 | 收藏、Wiki、待办、课程节点、底稿都是 `items` 表里的一行。模块决定怎么列、怎么编、Agent 默认干什么。 |
| 不登录外部平台 | 知乎 / 公众号 / 小红书只作为导入来源或导出目标的名字，不在本产品里授权。 |
| Agent 跟条目走 | 右栏对话绑定当前选中项。课程「设计一门课」是另一次独立长对话，不和学习页混在一起。 |
| Markdown 是正文 | 导入时外部 Agent 转好 Markdown；站内预览 / 编辑 / 对照。 |
| 删除可逆 | 悬停约 1 秒出现删除，无确认框；软删除进回收站，可按批次恢复。 |
| 导入导出是边界 | 第一版外部只开放：收藏导入、出稿导出。课程用的 PDF/EPUB 在设计对话里上传，不走这批外部接口。 |

当前明确不做：GitHub 仓库管理、看板/日历、优先级与重复待办、双向链接图谱、真实发布、多租户。

## 4. 总体结构

桌面 Web 工作台，浅色阅读界面。登录之后是同一套骨架：

```
┌ 顶栏：品牌 · 当前列表搜索 · 回收站 · 用户 · 退出 ─────────────┐
│ 导航 │                    工作区                         │
│ 收藏 │  左栏容器     中栏列表/树     正文/编辑     右栏 Agent │
│ Wiki │                                                    │
│ 待办 │                                                    │
│ 课程 │  （课程设计和阅读是另一套布局，见第 5.4 节）          │
│ 出稿 │                                                    │
│ 设置 │                                                    │
└────────────────────────────────────────────────────────────┘
```

- 五个主模块：收藏、Wiki、待办、课程、出稿。
- 回收站、设置是覆盖层，切换时不卸载当前模块，避免每次回来都跳回第一篇。
- 正文统一 Markdown：预览、源码、对照。
- 数据在本机 SQLite（`data/workbench.db`）。前端 Vite + React，后端 Hono，对话走 Cursor SDK。

## 5. 功能模块

### 5.1 收藏（输入）

招牌布局，也是导入入口。

**容器**：收藏夹。导入时指定夹名，没有则自动创建。

**三栏**：

1. 收藏夹列表：名称 + 篇数。
2. 当前夹的文章列表：标题、作者、原文日期。
3. 阅读器：标题、作者、日期、原文链接、Markdown 正文。只读。

**Agent**：上下文是当前夹 + 当前篇，用来讨论、提炼、拆大纲或改写。

**导入**（不在收藏页粘贴）：

外部 Agent 调用 MCP `import_collection_item`，或 `POST /api/import/items`。必填：`collectionName`、`title`、`body`（Markdown）。可选：原文链接、作者、`answer`/`article`、原文时间、主题数组。主题字段会入库，收藏页目前不展示筛选。

查询工具：`list_collections`、`list_collection_items`。

**删除**：列表项悬停 1 秒 → 删除 → 进回收站。

---

### 5.2 Wiki（整理）

把读过的东西写成自己的长文，用树而不是夹。

**左栏**：可嵌套页面树。折叠展开（记在浏览器）、拖拽改父级和顺序。顶栏 `+` 建根页面；也可在当前页下新建。删父页时，整棵子树作为一批进回收站。

**中栏**：当前页。面包屑式从属关系体现在树上。Markdown 可编辑（预览 / 编辑 / 对照）。

**Agent**：上下文是当前 Wiki 页（含祖先路径）。

Wiki 的树、收藏夹、（后端仍保留的）主题，三套分组不要混：夹是外部导入容器，树是 Wiki 自己的目录。

---

### 5.3 待办（行动）

把「以后要处理」从文档里抽出来，但不做成看板。

**左栏视图**：未完成 / 今天 / 全部。

**中栏**：勾选、标题、截止日期。勾选不离开列表。

**右栏**：当前任务的 Markdown 备注；可链接到 Wiki 或其它条目；Agent 跟这条待办走（帮拆解、改备注、建议下一步）。

没有优先级、子任务、重复规则、日历。

---

### 5.4 课程（学习）

课程是独立容器，不占用 Wiki 树。分三种界面。

#### 书架

只列出 **已确认**（`status=ready`）的书。封面卡片 + 进度。悬停可删整门课（不是单课）。入口「写一门课」打开生成页。

#### 生成页（设计对话）

这不是三栏阅读器。

1. 开一场独立长对话。可绑定收藏夹、Wiki/收藏条目，可上传 PDF / EPUB 等文本作为材料。
2. Agent 先拷问目标、基础、范围、用途，再给可嵌套大纲。
3. 大纲列表和思维导图是**同一棵树**。章可嵌套；只有叶子（课时）以后会生成正文。
4. 「确认目录」之后，目录锁定，进入阅读；不能从阅读再改回设计。
5. 未确认的草稿留在历史里，不会出现在书架上。历史里：未完成的可以续写；已确认且仍有对话的是只读档案，可「打开这本书」，也可单独删档案。

离开生成页，草稿仍在历史中。

#### 阅读页

三栏：目录树（带进度）| 课时正文（文档 / Canvas）| Agent（只跟当前课时）。

- 第一次点开叶子课时，按「课程背景 + 本章」流式生成讲义，**固化**，以后打开不再重写（用户明确要求重写除外）。
- Canvas 是受控的分步示意（波形 / 频谱 / 变换 / 树等固定图形），不是任意 HTML。
- 「返回书架」。不能从阅读再进设计。

---

### 5.5 出稿（输出）

一份底稿，三个平台变体，只导出不发布。

**左栏**：稿件列表。每篇标公众号 / 小红书 / 知乎是否已可导出。可筛「全部 / 可导出」。

**中栏标签**：底稿 | 公众号 | 小红书 | 知乎专栏。

各平台共用字段思路：标题、正文、摘要、标签、封面说明、配图说明（画面描述，不是图片文件）。可从底稿生成初稿再改。改完后「标为可导出」。

**Agent**：上下文是当前稿 + 当前标签，按平台改语气、压缩、补配图说明。

**导出**：外部 Agent 先 `list_exportable_variants`，再 `export_variant(draftId, platform)` 取走包。未标可导出会失败。工作台不跟踪是否真的发到了平台。

## 6. 横切能力

### 6.1 Agent

- 实现：本机 Cursor Agent（`CURSOR_API_KEY`，设置页填写，写入 `.env`）。
- 绑定：`conversations` 一对一挂在条目上，可 resume。
- 课程设计对话挂在课程条目上；学习对话挂在课时条目上。
- 不改工作区代码，除非用户明确要求。

### 6.2 回收站

悬停 1 秒删除，无确认。软删除。Wiki 子树、整门课按批次。顶栏「回收站」可恢复。

### 6.3 登录与公网

单用户会话：HttpOnly Cookie，密码 scrypt 哈希进 `.env`。未登录时业务接口 401。

- 尚未设账号：登录页变为「创建登录账号」。
- 已设账号：用户名 + 密码。设置里可改。
- 默认监听 `0.0.0.0:8787`。生产 `pnpm build && pnpm start` 由后端托管前端静态资源。公网应加 HTTPS 反代。

网页登录和 MCP token 是两套凭证。

### 6.4 MCP / HTTP 边界

外部 Agent 不必和仓库在同一台机器。HTTP MCP：`{公开地址}/mcp`，请求头 `Authorization: Bearer <WORKBENCH_TOKEN>`。

| 方向 | 工具 | 对应 HTTP |
| --- | --- | --- |
| 导入 | `import_collection_item` | `POST /api/import/items` |
| 查询收藏 | `list_collections` / `list_collection_items` | 站内 API（MCP 封装） |
| 列出可导出 | `list_exportable_variants` | `GET /api/export/variants` |
| 取出变体 | `export_variant` | `GET /api/export/variants/:draftId/:platform` |

未配置 token 时这些接口拒绝。设置页有接入 JSON 和字段说明。

### 6.5 设置

- 登录账号
- Cursor API Key（只给站内 Agent）
- Workbench Token + MCP 公开地址
- 导入 / 导出工具字段说明

## 7. 数据骨架

统一 `items`（类型区分模块）：

| type | 模块 |
| --- | --- |
| `collection_item` | 收藏 |
| `wiki` | Wiki 页（`parentId` + `sortOrder` 成树） |
| `todo` | 待办（`status` / `dueAt` / `completedAt`） |
| `draft` | 出稿底稿；`draft_variants` 存三平台 |
| `course` | 一门课（设计中或已确认） |
| `course_node` | 章或课时 |

其它表：`collections`、`collection_items`、条目链接、对话与消息、课程材料与绑定、课时 canvas。删除用 `deletedAt` + `trashBatchId`。

## 8. 主路径（用户故事）

1. 外部 Agent 把知乎收藏导入某个夹。
2. 在收藏三栏阅读，右侧 Agent 拆要点，必要时写入 Wiki。
3. 想学这块：开课程设计，绑定该夹或 Wiki 页，对话确认大纲，生成书架上的书。
4. 按目录上课，讲义固化；Agent 给当前课时补例子或 Canvas。
5. 从课程或收藏写底稿，生成三平台变体，标可导出。
6. 另一个外部 Agent 取走变体包，去各平台发布。

---

## 9. 版本边界

**现在做了**：统一条目；五模块；条目级 Agent；回收站；登录；HTTP MCP 导入收藏 / 导出变体；课程设计对话 + 书架 + 阅读固化。

**故意没做**：登录外部内容平台、GitHub 模块、团队账号、日历看板、真实发布回执、通用条目 CRUD 给外部。
