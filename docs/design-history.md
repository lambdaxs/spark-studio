# Spark Studio · 讨论过程与设计决策

本文给**下一任 AI / 协作者**用：记录产品是怎么讨论出来的、哪些已经拍板、哪些中途改过。当前功能以 [product.md](./product.md) 为准；界面绘图以 [product-design-spec.md](./product-design-spec.md) 为准。

原始对齐发生在 2026-09-07～09-08，对话很长。这里只保留**结论、理由、后来的修正**，不要再从零问一遍已经锁死的问题。

---

## 0. 给下一任 AI 的工作方式

当时的对齐习惯（请沿用，除非用户改口）：

1. **先理解再开工。** 用户多次写「理解需求后与我对齐再开工」。先复述成可执行规则，列出会改数据模型的分歧，等人点头。
2. **一次只钉一刀。** 大问题拆成单选题（A/B），推荐项写清楚，等「接受」再问下一刀。
3. **不要发明模块。** 用户没点头的东西不要做（GitHub、分组 UI、真发布、看板等）。
4. **改界面先对照已锁定的壳。** 设计稿里若出现已否掉的能力（分组 pill、深色轨、假对话），不要为了 1:1 画稿把产品改回去。
5. **先读这三份文档，再读代码。** `docs/product.md` → 本文 → `docs/product-design-spec.md`。仓库：https://github.com/lambdaxs/spark-studio

## 1. 起点（用户原话）

用户想把日常软件收进一个 Web 工作台，并列出五块：

1. 知乎收藏助手
2. AI 课程生成 + 学习
3. 待办清单 + 知识库 Wiki
4. 多媒体运营文章（公众号、小红书、知乎专栏）
5. GitHub 开源项目管理

硬约束：每块都要能接一个 Cursor Agent，**基于正在浏览的数据**讨论和产出，而不是一个没有画面的通用对话框。

助手把产品理解成三层，而不是五个网站并排：

1. 你正在看的东西
2. 沉淀下来的统一数据（模块能互相引用）
3. 贴在当前页上的 Cursor Agent

跨模块才是比「五个收藏夹 + 一个 ChatGPT」强的地方。第一版建议只给用户自己用。

用户确认：**第一版只做给自己用**，并且钉死输入输出边界：

- 知乎收藏夹只存标题和内容，**提供导入接口，不登录知乎**，抓取由其他 Agent 做。
- 公众号 / 小红书 / 知乎专栏**不登录去发**，站内把素材准备好，提供导出接口，其他 Agent 去发。

此后产品定位改成：**知识中枢，不是平台客户端。** 抓取和发布都在系统外面。

## 2. 锁定决策（按讨论顺序）

每条都是用户明确接受过的。后面「已修正」的以第 3 节为准。

### 2.1 数据与范围

| 决策 | 选择 | 理由 / 备注 |
| --- | --- | --- |
| 用户规模 | 单用户自用 | 先打通浏览 → Agent → 回写 |
| 底层模型 | **一套知识条目，模块是视图** | 否则五个库，Agent 没法把收藏变成课再变成稿 |
| 体验 | 统一底层、**分开界面** | 用户同意模型，但要求各模块体验要好 |
| GitHub | **v1 不做** | 用户中途叫停；以后单开一轮 |
| 导入导出形态 | **HTTP JSON 为本，MCP 包一层** | 前端和 curl 走同一套；不维护两套逻辑 |
| 外部开放面 | 只开放**收藏导入**和**出稿导出** | 不做任意条目 CRUD；PDF/EPUB 只在课程设计里上传 |
| 开工顺序 | 先做壳 + 条目 + 收藏 + 导入 + 右栏 Agent | 最短闭环；课程最重，放后面 |

### 2.2 收藏

| 决策 | 选择 |
| --- | --- |
| 容器 | **保留收藏夹**，不摊成一个大列表 |
| 阅读 | 桌面 **三栏**：夹 \| 列表 \| 正文；Agent 跟当前夹 + 当前篇 |
| 最小字段 | 标题、Markdown 正文、所属夹、原文链接、作者、形态（回答/文章）、原文时间、导入时间。不存赞数、评论 |
| 中栏一行 | 标题、作者、原文日期。不放摘要、链接、类型标签 |
| 分组 | 当初接受「全局可多选分组 + 夹内筛选」。**后来从 UI 拿掉，见 3.1** |

### 2.3 Wiki 与待办

| 决策 | 选择 |
| --- | --- |
| 入口 | **两个入口**，不要塞进同一页。底层仍是同一类条目 |
| Wiki 左栏 | **可嵌套页面树**（不是扁平列表 + 分组） |
| 三种分组不要混 | 收藏夹 = 外部导入容器；分组 = 跨模块打标；树 = Wiki 自己的目录 |
| Wiki 字段 | 标题、正文、父页面、同级排序、创建/更新时间。不要 slug/封面/发布状态。第一版不做双向链接图谱 |
| 待办字段 | 标题、未完成/已完成、Markdown 备注、可选截止日期、可选链到 Wiki/收藏。**不做**优先级、重复、子任务、提醒 |
| 待办界面 | 同样三栏：视图（未完成/今天/全部）\| 任务列表 \| 备注 + 链接 + Agent。不做看板、不做日历主视图 |

### 2.4 课程

用户补充了生成方式，并修正了「先不做章」：有大纲和导图，目录必须是树。

路径：设计对话（绑 PDF/EPUB/收藏夹/Wiki）→ Agent 拷问 → 大纲 + 思维导图 → 确认后才成为课程目录 → 点叶子再生成该课正文。

| 决策 | 选择 |
| --- | --- |
| 与 Wiki | **独立课程容器**，不占用 Wiki 树 |
| 大纲 / 导图 / 确认后的目录 | **同一棵可嵌套的树**。章只负责结构，**只有叶子点开才生成正文** |
| 正文 | **生成一次固化**，再点开不重写；要改必须用户明确要求 |
| Canvas | **正文必有、canvas 可选、都固化**；学习时文档/Canvas 切换。受控组件，不跑任意 HTML/JS |
| 谁决定 canvas | 生成时 Agent 判断；学的过程中仍可对话补/改 canvas，不自动覆盖正文 |
| 两套界面 | **设计是对话流，学习是三栏**（目录树 \| 课时 \| Agent）。不要画在同一屏 |

后来课程 UI 整段产品化过一次（书架 / 生成页 / 阅读），见 3.3。原则未翻：独立容器、同一棵树、确认后锁目录、正文固化、阅读页 Agent 只跟当前课时。

### 2.5 出稿

| 决策 | 选择 |
| --- | --- |
| 结构 | **一份底稿 + 三平台变体**，不是每个平台从零各写一篇 |
| 界面 | 三栏：稿件列表 \| 底稿/公众号/小红书/知乎专栏标签 \| Agent |
| 变体字段 | 共用一套：平台、标题、正文、摘要、标签、封面说明、配图说明（画面描述不是图文件）、未生成/可导出、更新时间 |
| 发布 | **只导出不发布** |

### 2.6 Agent

| 决策 | 选择 |
| --- | --- |
| 绑定 | **一条知识一份对话**，切走再回来可续 |
| 课程设计 | **另一次独立长对话**，不和「学某一课」混 |
| 不要 | 全局一个对话框横跨所有模块 |
| 实现 | **Cursor SDK 本机 Agent**（`CURSOR_API_KEY`），不是通用 LLM HTTP API |
| 流式 | SDK 是 `run.stream()`，应用层再包成 Hono SSE 给前端 |

### 2.7 技术栈（开工前锁定）

本机、单用户、TypeScript 一套：

- 前端：Vite + React
- 后端：Hono（Node），常驻进程（不用 Next.js）
- 数据：SQLite `data/workbench.db`（不用 Postgres）
- 对话：`@cursor/sdk`
- 外部：同一套 HTTP，MCP 外包一层

当时进程只绑 `127.0.0.1`。后来为了公网改成默听 `0.0.0.0` 并加登录，见 3.5。

## 3. 落地后改过的决策（重要）

这些会覆盖第 2 节里的旧结论。下一任 AI **以这一节为新真相**。

### 3.1 打标分组从界面拿掉

当初为了收藏夹里文章太多，加了全局可多选「分组」。实现后又要求 **先在产品中移除打标分组**。

- UI：不要学科 pill、分组筛选、「打标分组」输入框。
- 后端字段和 MCP 的 `groups` 仍可能入库，收藏页不展示。
- 设计稿里若还有分组，**不要为了对齐画稿加回去**。

### 3.2 视觉与 Markdown

对照 `prd-image-2.png` 等设计稿：

- 导航从深色轨改成浅暖灰，选中浅蓝底 + 左边蓝条。
- Markdown 禁止裸 textarea：预览 / 编辑（CodeMirror）/ 对照。Wiki、出稿走完整三态；待办备注默认阅读，点进去才出现编辑工具（quiet）。
- 待办对齐设计稿时拍板：顶上「+ 新建任务」（1A）；截止日期当元信息、点一下才改（2B）；分组不做（3）。

### 3.3 删除与回收站

统一规则（收藏、Wiki、待办、课程、出稿）：

- 列表行悬停 **满 1 秒** 才显示「删除」；移开收起。
- 点击 **无确认框**。
- 软删除进回收站；顶栏有回收站，可恢复（拍板 1B，不是只留数据不做入口）。
- Wiki 删父页 = **整棵子树一批**（2A）。
- 课程只删 **整门课**，不删单个课时（3A）。
- 收藏夹本身这期不删。

### 3.4 Wiki 树增强

对照设计稿后加了：子页面折叠展开（localStorage）、HTML5 拖拽改父级和顺序。顶栏 `+` 建根页；可在当前页下新建。

### 3.5 课程改成「书架 / 生成 / 阅读」

用户认为当时课程「没有任何产品化」。重新对齐后：

| 点 | 结论 |
| --- | --- |
| 进课程模块 | **安静书架**，只摆已生成的书（`status=ready`），封面卡带进度 |
| 写书 | 独立生成页，不是书架上嵌一块对话框 |
| 点书 | 进入阅读；**不能再改大纲/目录** |
| 草稿 | 不算书；历史里续写未完成的对话 |
| 已出书的历史 | **留下只读档案**：能回看对话和冻结大纲，输入和确认按钮关掉；「打开这本书」进阅读 |
| 档案删除 | 可以单独删档案；删整本书会带走剩余档案 |
| 历史入口 | 生成页对话框 **右下角图标**，点开侧栏，不常驻占位 |
| 生成页布局 | 一开始 **只留对话**；有大纲后才左对话 / 右大纲\|导图切换。材料收进一个图标入口 |
| 确认按钮 | **只锁目录**，然后 **直接打开阅读页**；正文第一次点开再 SSE 生成并固化 |
| 阅读 Agent | 要，但 **只跟当前课时** |
| 离开生成页 | **直接回书架**，草稿进历史 |

模块切换曾会卸载页面，收藏总跳回第一篇。改成首次访问才挂载，用 `hidden` 保活；回收站/设置是覆盖层，不拆当前模块。

### 3.6 设置、MCP、公网登录

| 点 | 结论 |
| --- | --- |
| API Key | 左下角设置；写入项目 `.env`，界面只显示末四位 |
| MCP 形态 | 用户否掉「Agent 与项目必须同一台机器的 stdio」。改为 **HTTP MCP + Bearer token** |
| 设置页 | 说明接入 JSON、`import_collection_item` 字段、出稿 `list_exportable_variants` / `export_variant` |
| 鉴权 | 未配 token → 导入/导出/MCP 503；token 错 → 401。网页会话和 MCP token **两套** |
| 公网 | 用户要求放到公网并做登录页。单用户账号，scrypt 哈希，HttpOnly Cookie。业务 API 未登录 401 |
| 监听 | 默认 `0.0.0.0:8787`；生产 `pnpm build && pnpm start` 由 Hono 托管 `web/dist` |

## 4. 明确拒绝过的东西

不要再提议做成默认，除非用户重新要：

- 登录知乎 / 微信 / 小红书，或在站内真发布
- v1 的 GitHub 模块
- 看板、日历主视图、优先级、子任务、重复待办
- 全局万能聊天（不跟当前条目）
- 课程目录写进 Wiki 树
- 课时每次点开都重新生成
- 任意 HTML/JS 的课程 canvas
- 为对齐某张设计稿而恢复分组 UI
- 删除时弹确认框
- 外部通用 CRUD
- 多租户 / 团队
